Solution / 01

题目需求和内容梳理

先把题目要求翻译成内容结构，再决定方案怎么落地。

01 / 04
L1 宏观题目要求→教师 / 学生需求→内容问题
单页只讲一个观点：先定边界，再定方案。
这一页只做一件事：把题目要求翻译成内容结构。主讲顺序是先讲题目要求，再讲教师和学生的角色需求，接着讲为什么静态课件会出现内容问题，最后把方案入口收束到内容梳理和双端协作。 讲的时候要把 L1-L3 层级说清楚：L1 是题目要求，L2 是教师/学生需求，L3 是内容问题与方案入口。不要把技术实现提前抬上来，这一页的职责是定边界，不是讲算法。
Solution / 02

双端解决方案总览

一套底座，两端分工，统一节点语言后再谈协作。

02 / 04
L2 中观共享底座→双端协作→学习闭环
量化锚点：page / node / second / node-insights。
这一页的核心是共享底座。对外要讲成一句话：一套底座，两端分工。上半部分是总流程，下半部分是节点化学习底座，再往下分别展开教师端和学生端，最后底部用系统级、中观级和微观级抽象层收束。 这里要强调量化锚点：current_page、understanding_level、resume_sec、node-insights。它们不是附属字段，而是学生端和教师端都能消费的共同语言。
Solution / 03

教师端：讲授内容

把课件变成可讲、可改、可发布的讲授内容。

03 / 04
L3 微观I/O 链路→理论 / 公式 / 示例
量化节点：current_page / resume_sec / understanding_level。
这一页要把 I/O 链路讲完整：输入是 PPT / PDF 和课件要点，处理中间有页级摘要、节点聚合、脚本生成和教师校准，输出是可讲、可改、可发布的讲授内容。 这一页的深度要落在三件事上：一，理论上为什么要先做页级摘要；二，公式上为什么可以写成“脚本 = Σ(页级摘要 × 节点聚合) + 教师校准”；三，示例上如何从三类输入得到四段输出和一份可编辑脚本。
Solution / 04

学生端：断点续学

把问题回链到节点，再继续学下去。

04 / 04
L3 微观current_page → understanding_level → resume_sec
核心不是答完，而是接着学。
这一页补上学生端。主讲顺序是：先讲输入是什么，再讲系统怎么处理，再讲输出怎么帮助学生继续学。 要特别强调三态理解：none、partial、full。none 代表需要重讲，partial 代表需要补充，full 代表可以继续推进。这个三态不是形式化装饰，而是续接位置和讲授节奏的依据。
