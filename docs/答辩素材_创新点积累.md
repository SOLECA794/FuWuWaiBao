## 创新点一：可编程讲授脚本语言

**标签**：结构化脚本 / 节点级续接 / 粒度控制

**问题背景**：
传统 AI 讲稿生成输出一长段文本，教师无法控制节奏，学生打断提问后只能从头续接，问答与讲授是割裂的。

**技术实现**：
- 每个知识节点（node）的讲稿是一个 segment 数组
- 每个 segment 携带 6 个结构化字段：segment_type（opening/explanation/example/interaction/transition/summary）、estimated_seconds、interaction_hint（教师互动话术）、knowledge_card（术语/定义/公式/标签）、difficulty、segment_id
- 三阶段 pipeline 中 Stage 3 输出增强 schema（`build_enhanced_script_schema`）
- 兼容 `json_object` 模式，处理 `node_id`/`node_ids` 两种 LLM 输出格式

**可验证效果**：
- 每节点 2-4 个 segment，总时长 75-150 秒，全部带 interaction_hint + knowledge_card

**关联指标**：知识点识别准确率 >=80%、问答续接精度（segment_id 级）

## 创新点二：跨页语义节点聚合

**标签**：语义聚类 / 三阶段 pipeline / 从碎片到结构

**问题背景**：
传统按页提取文本生成讲稿，知识点边界被页面切割。跨 3-5 页才构成完整概念。

**技术实现**：
- Stage 1：课件理解 → normalized_markdown + key_points
- Stage 2：LLM 跨页语义聚类 → node 数组（node_id/title/summary/source_span/prerequisites）
- Stage 3：节点级脚本生成（见创新点一）
- `_extract_json` 兼容 `{...}` 对象和 `[...]` 数组输出

**可验证效果**：
- 4 页课件 → 5 个语义节点（而非 4 个页节点），自动推导 prerequisite 关系

## 创新点三：多模态课件理解

**标签**：视觉语义化 / 图文融合 / 公式图表识别

**问题背景**：
纯文本提取导致公式、图表、流程图、排版信息全部丢失，知识点识别质量天花板低。

**技术实现**：
- PPTX：`_extract_pptx_images()` 提取嵌入图片 → base64 → glm-4v-flash 视觉模型 → visual_description
- PDF：`page.get_pixmap(dpi=150)` → PNG → base64 → glm-4v-flash → visual_description
- AI_USE_VISION=true 控制开关，无需 LibreOffice

**可验证效果**：
- Slide 3 的 75KB PNG 正确识别为"网络层和数据平面"章节目标页

## 创新点四：LLM 意图驱动的三态理解与智能续接

**标签**：理解程度评估 / 节奏调整 / 智能续接

**问题背景**：
传统问答仅判断"需要重讲/不需要重讲"二态，需求要求"通过 NLP 分析学生理解程度，自动定位原节点"。

**技术实现**：
- 三态：none（完全未理解）→ partial（部分理解）→ full（已理解可推进）
- `_predict_understanding()`：LLM 输入问题+内容+历史 → 输出 `{"understanding_level": "none|partial|full"}`
- 续接策略：full→下一页，partial→当前页偏移15秒，none→当前页起始
- 新增字段：resume_node_id、resume_sec
- 苏格拉底式回答，不直接给答案

**可验证效果**：
- "听不懂" → none → resume_page=1, resume_sec=0
- "转发的具体过程？" → partial → resume_page=2, resume_sec=15
- "明白了请继续" → full → resume_page=3

## 技术决策记录

| 决策 | 方案 | 理由 |
|------|------|------|
| PPTX 图片提取 | python-pptx 原生提取嵌入图片 | 原图最高分辨率，无外部依赖 |
| 视觉模型 | glm-4v-flash | 可用配额，支持 base64，0.01 元/次 |
| JSON Schema | json_object + prompt 约束 | glm-4-flash 不支持 strict schema |
| node_id 兼容 | _resolve_script_node_id() | LLM 有时输出 node_ids 数组 |
