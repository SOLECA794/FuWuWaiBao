# 启智云双端解决方案图 PPT 内容卡

> 用途：你负责的“解决方案”部分，适合直接拿去做图形化 PPT。
>
> 内容原则：先定内容，再定风格。这里不讲美工，只讲页面应该讲什么、画什么。

---

## 一、这一部分的叙事起点

不要从技术名词开始，也不要从架构图开始。

这一部分最自然的起点是：**题目要求到底要我们解决什么，教师和学生分别需要什么。**

所以整段内容的逻辑顺序应该是：

1. 题目需求和内容梳理。
2. 双端解决方案总览。
3. 教师端解决什么。
4. 学生端解决什么。
5. 双端如何联动成一个完整故事链。
6. 需求如何对应到算法处理方式。

---

## 二、这一段适合做成的页面顺序

### 第 1 页：题目需求和内容梳理

**页面目标**：把问题边界和用户需求说清楚。

**核心句**：

- 题目要求不是单点功能，而是一条完整的教学闭环。
- 我们先梳理题目需求，再决定方案怎么落地。

**关键词句**：

- 课件讲解
- 实时问答
- 进度续接
- 结构化讲授
- 自主学习场景

**可画流程**：

题目要求
→ 教师需求 / 学生需求
→ 内容层问题
→ 方案设计入口

---

### 第 2 页：双端解决方案总览

**页面目标**：先给评委一张总图，看懂“我们怎么分工”。

**核心句**：

- 启智云不是两个孤立功能，而是一套底座上的双端协作。
- 教师端负责生成和组织，学生端负责提问和续学。

**关键词句**：

- 一套底座
- 两端分工
- 节点语言统一
- 教师侧生成与管理
- 学生侧问答与续接

**可画流程**：

题目需求
→ 内容梳理
→ 节点化学习底座
→ 教师端 / 学生端协作
→ 学习闭环

---

### 第 3 页：教师端解决什么

**页面目标**：明确教师端做了什么、解决了什么问题。

**核心句**：

- 教师端的目标是把课件变成可讲、可改、可发布的讲授内容。
- AI 负责生成，教师负责把控节奏和最终呈现。

**关键词句**：

- 知识点识别
- 开场白 / 讲解 / 过渡语
- 结构化脚本
- 教师可编辑
- 语音 / 数字人讲授

**可画流程**：

PPT / PDF
→ 页级摘要
→ 节点聚合
→ 脚本生成
→ 教师编辑
→ 发布到课程

**解决的问题**：

- 静态课件不好直接讲。
- 讲稿整理成本高。
- 教师需要可控、可改、可复用的讲授内容。

---

### 第 4 页：学生端解决什么

**页面目标**：明确学生端做了什么、解决了什么问题。

**核心句**：

- 学生端的目标不是“只给答案”，而是让学生在当前页、当前节点上继续学。
- 问答不是终点，续接才是闭环的关键。

**关键词句**：

- 当前页优先
- 当前节点优先
- 上下文问答
- 多轮交互
- 理解程度判断
- 断点续接

**可画流程**：

当前页 / 当前节点 / 历史上下文
→ 上下文问答
→ 理解程度判断
→ 续接策略
→ 补讲 / 重讲 / 继续推进

**解决的问题**：

- 缺课后补学难。
- 练习 / 提问后的复盘难。
- 学生容易在理解断点处停住。

---

### 第 5 页：双端联动故事链

**页面目标**：把教师端和学生端串成一个完整故事。

**核心句**：

- 教师端生成内容，学生端围绕内容学习。
- 学生问答后，系统把问题回链到节点，再继续讲下去。

**关键词句**：

- 教师上传课件
- 系统解析并生成脚本
- 教师编辑后发布
- 学生在节点处提问
- 系统结合上下文回答
- 根据理解程度续接

**可画流程**：

教师上传课件
→ 结构化脚本生成
→ 教师编辑与发布
→ 学生进入当前节点学习
→ 提问 / 理解判断
→ 续接讲解
→ 教师看到共性卡点

**这一页的作用**：

它不是结果预览，而是把“我们做了什么”讲成一条完整的使用链路。

---

### 第 6 页：需求到算法的对应表

**页面目标**：把功能需求和算法处理方式一一对上。

**核心句**：

- 不是先有算法，再找场景。
- 而是先有需求，再拆成对应的算法处理链路。

**建议表格**：

| 用户需求 | 算法处理方式 | 最终效果 |
| --- | --- | --- |
| 课件讲解 | 课件解析 + 跨页语义聚合 + 脚本生成 | 可讲授结构化脚本 |
| 实时问答 | 当前页优先召回 + 上下文关联 + 溯源生成 | 课件相关答案 |
| 进度续接 | 理解程度分析 + 节奏策略 + 节点回跳 | 续接到正确位置 |

**可画流程**：

需求
→ 算法处理
→ 页面输出

---

## 三、这一部分最适合给队友的统一口径

你可以直接这样说：

> 这一部分先不讲架构，而是先把题目需求梳理清楚，再讲我们双端到底分别解决什么问题。教师端重点解决“怎么讲”，学生端重点解决“怎么问、怎么接”，最后再把这些功能映射到算法处理方式上。

---

## 四、这一部分的核心抓手

如果你要做成图形化 PPT，最重要的不是字多，而是每页都能一句话说清：

1. 这一页解决什么问题。
2. 这一页对应什么功能。
3. 这一页在整条链路里处于什么位置。
