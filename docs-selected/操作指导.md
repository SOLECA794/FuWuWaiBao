# PPT升级修改执行指南
## 执行总览
基于已生成的《PPT逐页技术深度升级修改意见文档》，结合以下所有要求进行最终校准，输出**正式版修改意见文档V2.0**。所有操作必须严格遵循本提示词的约束和要求，禁止任何无依据的自主发挥。

---

## 一、不可动摇的全局约束（违反即不合格）
1. **真实性红线**：所有内容100%基于`docs-selected/`目录文档和项目源代码，禁止任何虚构的功能、算法、数据和技术
2. **表述红线（精准区分）**：
   - ✅ 允许保留通用技术专有名词（如Redis、SHA-256、SSE、JSON Schema等），**必须同时说明该技术在本项目中的应用价值和达到的量化效果**
   - ❌ 绝对禁止出现任何项目特有的变量名、函数名、接口名、数据库字段名和内部数据流名称，所有项目专属细节必须升级为工程化抽象口径
   - 标准示例：
     - 错误："我们用了user_id和node_id存学习状态"
     - 正确："基于用户-课程-知识点三维标识实现状态快照，采用SHA-256哈希保证缓存一致性"
     - 错误："调用了dify_client.go的postJSON方法"
     - 正确："引入分布式任务调度机制，支持异步任务的重试与降级"
3. **逻辑红线**：所有修改（包括页面拆分、合并、顺序调整、标题修改）**必须明确写出修改依据和预期效果**，无依据的修改一律无效


---

## 三、核心优化原则
### 3.1 架构部分专项优化（最高优先级）
1. 明确架构页本质：评委看架构页，最想知道的是**「你的系统是怎么组织起来解决核心痛点的，为什么这么组织，这样组织能带来什么不可替代的好处」**，而不是看组件列表
   - 禁止强调"薄业务重编排"表述
2. **完全自主判断架构核心思想**：禁止任何预设的架构思想框架，完全基于项目真实实现，提炼最突出、最有说服力、最能体现工程深度的设计思想
   - 所有提炼必须有明确的`docs-selected`文档或源代码依据
3. **完全自主决定架构页面结构**：允许对架构部分的页面进行任何形式的拆分、合并、调整顺序、修改标题、增减页数
   - 唯一判断标准：是否能让上下文衔接更顺畅、逻辑更清晰、信息传递效率更高
4. **完全自主选择表述方式**：没有任何固定的表述结构要求，根据内容特点选择最清晰、最准确、最有说服力的表述方式即可
5. 可参考资料：`@docs-selected\3-架构与算法分析\架构修改指导.md`中列举的模型模式，但不受任何预设架构设计模式限制，完全基于项目实际情况设计

### 3.2 分工部分专项优化
1. 禁止直接决断采用某一种分工表述方式，必须完整对比以下两种主流方案的优劣，给出各自的适用场景和取舍依据，最终提供推荐意见供用户自行选择：
   - 方案A：`docs-selected`文档中参考的**主责锚点+全员协同模式**
   - 方案B：原PPT中描述的**平行角色分工模式**
2. 对比维度必须包含：优势、劣势、适合的团队规模、适合的答辩场景、给评委的直观感受
3. 必须提供两种方案的**完整表述示例**，内容严格基于`docs-selected`文档或原PPT真实内容
4. 表述风格要求：严肃、专业、具体，绝对禁止口语化、抒情化、泛化的表述方式

### 3.3 全局表述优化
1. 没有任何固定的表述结构要求，"设计动机→实现机制→业务价值"仅作为众多可能的表述方式之一提供参考，不做任何推荐或强制要求
2. 所有表述的唯一判断标准：是否清晰、准确、有说服力地传达了信息，是否能让评委快速理解并认可
3. 所有底层技术细节必须升级为工程化抽象口径，同时保留有价值的通用技术专有名词并说明其应用价值
4. 优化页面之间的过渡衔接，确保整个PPT的叙事逻辑是一条连续的因果链，而不是孤立的页面堆砌

---

## 四、输出要求
1. 所有重构和优化的部分必须用**【自主优化】**标注，同时明确写出**修改依据**和**预期效果**
2. 技术点汇总表和质量自检清单必须同步更新，与修改后的内容完全一致
3. **PPT 整体结构确认**：对ppt每页 编号-主旨标题-核心内容/主旨的整体结构确认（表格形式），确保每页内容与标题高度匹配，且整体结构合理、逻辑清晰、信息传递高效。
4. **PPT 逐页精确修改执行指令**：针对每一页，给出具体的修改执行指令，包括但不限于：修改内容、修改方式（拆分/合并/调整顺序/修改标题）、修改依据、预期效果等。
5. **整体优化建议**：针对整个PPT的结构、内容、表述方式等方面，给出综合性的优化建议，确保PPT的整体质量和效果达到最佳。针对全局表述，给出具体的优化建议，确保所有表述都清晰、准确、有说服力，并且能够让评委快速理解并认可。
6. **技术点汇总表**：列出PPT中涉及的所有核心技术点，说明其在项目中的应用价值和量化效果。
7. **质量自检清单**：基于上述约束和要求，制定一份详细的自检清单，确保所有修改都符合要求，并且PPT的整体质量得到保证。
8. **分工方案对比分析**：针对分工部分，给出两种主流方案的对比分析，包括优势、劣势、适合的团队规模、适合的答辩场景、给评委的直观感受等维度，并提供两种方案的完整表述示例。
9.  **架构部分优化说明**：明确说明架构部分的页面调整逻辑和理由，以及每一页的核心传达目标，确保架构部分能够清晰、准确、有说服力地传达系统的组织方式和设计思想。
11.  **修改依据和预期效果说明**：对于每一处修改，必须明确写出修改的依据（基于哪个`docs-selected`文档或源代码的哪个部分）和预期效果（希望通过这次修改达到什么样的改进）。
12. 所有表格和清单必须格式规范、对齐整齐，便于阅读和执行
