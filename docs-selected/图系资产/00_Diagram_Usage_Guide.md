## D01 — 五环业务闭环总览图

**对应PPT：** P02 方案总览
**小册子章节：** M02 总体方案
**目标文件：** `source/01_Business_Loop.mmd`

**用途说明：**
在答辩开场快速建立整体认知。评委看了这页就知道系统在做什么、五环不是孤立的环节而是因果链。

**防御的评委质询：**
| 质询 | 答案 |
|------|------|
| "你们系统核心能力是什么？" | 五环：可讲·可学·可问·可续·可评可优 |
| "你们的学情有什么独特之处？" | 四维数据回传，不是简单的登录统计 |

**最佳讲授话术：**
> "我们把教学闭环拆成五个环节。课件上传即生成讲稿——这是可讲；学生在端上播放学习——这是可学；遇疑随时提问，系统用苏格拉底式引导回答——这是可问；回答完成自动判定理解程度，续讲/补充/跳过精确选择——这是可续；学情四维数据回传教师端——这是可评可优。五个环节是一个因果链：解析是问答的前提，问答产出是续接的输入。"

## D02 — 系统技术编排架构全景图

**对应PPT：** P09 系统架构 + P10 设计决策
**小册子章节：** M03 架构深度解析
**目标文件：** `source/02_System_Architecture.mmd`

**用途说明：**
镇场页。展示系统的分层架构思想——编排与能力分离、双引擎降级、中间件拓扑。

**防御的评委质询：**
| 质询 | 答案 |
|------|------|
| "架构为什么这样分层？" | 编排层不做AI推理——AI延迟不可控，不能让编排层被拖慢 |
| "Dify挂了怎么办？" | 自动降级到本地Python引擎，切换对用户透明 |
| "你们用了哪些中间件？各负责什么？" | PG存关系型、Redis做缓存/队列、MinIO做对象存储 |

**最佳讲授话术：**
> "核心设计是编排与能力分离。Go后端只做状态编排和流式转发，不承担AI推理——因为AI推理3到5秒，不能让不可控的延迟影响整个系统。所有AI能力下沉到Dify，Dify挂了自动切到本地引擎。三层中间件各司其职——PG管结构化数据、Redis管缓存和队列、MinIO管文件存储。"

## D03 — 课件解析管线·三阶段解耦解析图

**对应PPT：** P06 智课生成 / P11 节点化 / P12 解析链
**小册子章节：** M04 算法专项解析
**目标文件：** `source/03_Parse_Pipeline.mmd`

**用途说明：**
展示技术硬实力。三阶段独立管线是核心创新——传统方案一次生成，我们分阶段可控。

**防御的评委质询：**
| 质询 | 答案 |
|------|------|
| "你们的解析和直接调大模型有什么区别？" | 三阶段解耦：Stage1理解→Stage2建树→Stage3生脚本，每阶段独立可优化 |
| "大模型输出不稳定怎么办？" | JSON Schema强制结构化约束 + LLM失败回退到预置模板 |
| "节点引用错了怎么办？" | normalize自动修复无效node_id + 双向对齐机制 |

**最佳讲授话术：**
> "解析不是一次性调用，而是三阶段独立管线。第一阶段理解课件结构、提取关键知识点；第二阶段构建节点树——每个节点是独立的教学单元；第三阶段逐节点生成讲稿脚本。每阶段有独立的JSON Schema约束——大模型输出格式异常会触发自动修复。任一阶段失败回退到预置模板，单阶段失败不影响整体。"

## D04 — 本页优先RAG+问答流程图

**对应PPT：** P07 学生端问答 / P13 问答续接链
**小册子章节：** M04 算法·问答
**目标文件：** `source/04_RAG_QA_Flow.mmd`

**用途说明：**
讲清楚"你们的AI不是通用聊天，而是课程知识约束的教学AI"。

**防御的评委质询：**
| 质询 | 答案 |
|------|------|
| "学生问的问题和课件无关怎么办？" | 三级级联上下文确保回答始终在课程范围内 |
| "AI直接给答案那不成了抄作业？" | 苏格拉底式约束——严禁直接给答案，先确认卡点再引导，以问题结尾 |
| "理解程度怎么判断的？" | LLM语义分析优先，不可用时降级到中文教育关键词匹配 |

**最佳讲授话术：**
> "问答不是让大模型自由发挥。我们做了三级上下文：先取当前教学节点的脚本——不够取整页——还不够取全页内容。然后用苏格拉底式约束——提示词里明确写了严禁直接给答案，要求它先确认学生卡点、再逐步引导、以问题结尾。最后判定理解程度——LLM判定优先，不可用时关键词匹配兜底。"

## D05 — 多态断点续学状态机图

**对应PPT：** P08 故事链 / P13 问答续接链
**小册子章节：** M04 算法·续接
**目标文件：** `source/05_Resume_StateMachine.mmd`

**用途说明：**
展示从"页级翻页续播"升级到"节点级精确续接"的技术深度。

**防御的评委质询：**
| 质询 | 答案 |
|------|------|
| "续接不就是记住看到第几页了吗？" | 我们是节点级——精确到教学单元内部位置，还带理解程度三态判定 |
| "理解程度三种状态分别怎么处理？" | none重讲、partial补充、full跳过 |

**最佳讲授话术：**
> "续接不是简单的'记得看到第几页'。我们精确到节点级别——不仅记录位置，还记录理解程度。学生没懂——回退重讲；部分懂了——补充卡点；完全懂了——跳过继续。打断时保存三元组：页面、节点、音频秒数——恢复时精确到之前断掉的位置。"

## D08 — 学情多维加权指数示意图

**对应PPT：** P06 学情查看
**小册子章节：** M04 算法·学情
**目标文件：** `source/08_Mastery_Score.mmd`

**用途说明：**
说明学情不是简单计数，而是多维度加权分析。

**防御的评委质询：**
| 质询 | 答案 |
|------|------|
| "学情不就是学生登录次数吗？" | 四个维度加权：提问频次、需重讲次数、会话数、停留时长 |
| "掌握度怎么计算的？" | 答对+0.08、答错-0.06、快速响应+0.02，区间[0,1] |

**最佳讲授话术：**
> "学情不是简单统计。我们综合四个维度——提问频次、需重讲次数、会话数、停留时长——加权得出难度指数。同时跟踪每个学生知识点的掌握度：答对加分、答错减分、快速响应额外加分。"

## D09 — 课件上传容错管道图

**对应PPT：** P12 解析链
**小册子章节：** M03 架构·课件管道
**目标文件：** `source/09_Upload_Pipeline.mmd`

**用途说明：**
展示"每一步都有容错方案"的工程思维。

**防御的评委质询：**
| 质询 | 答案 |
|------|------|
| "解析失败了课件还能上传吗？" | 不阻塞上传主流程——保留已存数据，标记解析状态 |
| "预览图生成失败了怎么办？" | 三级降级：实时渲染→占位图→空状态前端加载 |

**最佳讲授话术：**
> "上传管道每一步都有兜底。预览图三级降级——实时渲染优先，失败用占位图，还失败就标空让前端加载。AI解析失败不阻塞上传——数据先存着，后续可以重试。"

## D10 — 任务调度状态机图

**对应PPT：** P15 项目进展
**小册子章节：** M03 架构·任务调度
**目标文件：** `source/10_Task_Scheduler.mmd`

**用途说明：**
展示系统的后台自动调度能力，说明工程成熟度。

**防御的评委质询：**
| 质询 | 答案 |
|------|------|
| "定时任务失败了有没有自动恢复？" | 指数退避重试，最多3次 |
| "同时大量任务会崩吗？" | 10协程池+1000容量队列削峰 |

**最佳讲授话术：**
> "任务调度引擎采用状态机管理。pending→processing→success/failed。失败自动重试，退避策略是2^retryCount分钟——第一次2分钟、第二次4分钟、第三次8分钟，最多重试3次。10个worker协程并发消费队列，队列容量1000，压力大时削峰处理。"
