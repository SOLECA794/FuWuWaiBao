> 版本：V1.0 | 依据：操作指导 V1.3 | 基于 A12-v4.pptx 全文精读 + docs-selected 全部文档 + 项目全部源代码深度阅读

## 一、文档概述

### 1. 本次修改定位

本次修改是**基于已实现内容的技术表述优化与深度拔高**，不是内容重构，不是功能虚构。所有修改均可在 `docs-selected/` 或项目源代码中找到对应依据。

### 2. 整体修改思路

从 **"功能罗列"** 升级为 **"设计思想 + 实现机制 + 业务价值"** 三层表述体系。当前 PPT 的主要问题是：说了做了什么，但没说清楚为什么这样做、怎么做到的、这样做的效果是什么。评委看到的是功能清单，而不是 ==**工程深度**== 。

核心拔高方向：
- 把"我们实现了 X"升级为"我们面对 Y 问题，采用 Z 方案，因为……"
- 把技术名词堆砌升级为设计决策及其背后的工程考量
- 把静态描述升级为动态机制（数据怎么流转、异常怎么处理、状态怎么迁移）

### 3. 技术拔高方向（5 个重点）

| 方向 | 当前状态 | 拔高目标 |
|------|----------|----------|
| 1. 课件解析链路 | 只说了"多模态解析 + 跨页聚合" | 说清三阶段解耦 pipeline + 渐进增强 + 容错降级 |
| 2. 问答续接机制 | 只说了"理解程度 + 续接位置" | 说清三态判定实现 + 节点级续接精度 + 苏格拉底约束 |
| 3. 节点化底座 | 只说了"教学节点" | 说清知识图谱 + 脚本片段双映射 + 引用完整性修复 |
| 4. 架构韧性 | 只说了"Dify 编排 + Python 引擎" | 说清双引擎降级链 + 任务调度状态机 + SHA-256 缓存失效 |
| 5. 学情分析 | 只说了"提问记录 + 薄弱知识点" | 说清多维加权难度指数 + 艾宾浩斯掌握度模型 + 孤立引用扫描修复 |

### 4. 边界说明

- **未修改** PPT 整体骨架和页面顺序
- **未新增** 任何未实现功能
- **所有技术点** 均可在 `docs-selected/` 或源代码中找到对应依据
- 表述方式从"功能描述"升级为"设计决策 + 实现机制"，但底层事实不变

## 三、整体优化建议

### 1. 叙事逻辑衔接

当前 PPT 的叙事是"背景→痛点→方案→架构→算法→验证→团队"，逻辑通顺但缺少一条贯穿的技术主线。建议在方案总览（页面5）之后，每页都点题"节点化底座"这个核心概念：

- 页面6（教师端）："基于节点化底座，教师可编辑每个节点的脚本和音频"
- 页面7（学生端）："基于同一套节点化底座，学生的问答和续接都围绕节点展开"
- 页面11（算法）："节点化底座是全系统的统一语言"
