## 模块 1：开场案例或效果预览

**本页目的：** 让评委 30 秒内知道系统最终能做什么。

### 建议标题

**一份 PPT，如何变成会讲课、能答疑、可续学的 AI 智课？**

### 页面内容

**左侧：传统方式**
- 教师上传 PPT/PDF
- 需额外录制讲解视频
- 学生遇疑只能暂停、搜索、放弃

**右侧：我们的方式**
- 上传课件 → 自动生成讲授节点与讲稿
- 学生边学边问，AI 结合当前页回答
- 问答后自动回到原学习节点继续

### 一句话效果预览

> 把静态课件变成 **可讲授、可提问、可续接** 的 AI 互动智课。

### 讲解词（30 秒）

> 各位评委好。我们的系统面向泛雅平台高校通识课场景：教师上传一份 PPT，系统自动生成结构化讲稿和语音内容；学生学习时可以随时提问，AI 根据当前课件上下文回答，并在问答结束后自动续接学习进度。接下来我们从背景、痛点到完整方案展开说明。

## 模块 2：背景

**本页目的：** 说明为什么要做这件事。

### 建议标题

**教育数字化背景下，静态课件需要升级为 AI 互动智课**

### 页面内容

**行业背景**
- 泛雅平台沉淀海量 PPT/PDF 课程资源
- 《教育信息化 2.0》强调智慧学习环境与个性化教学
- 大模型、语音识别、多模态 AI 已具备落地条件

**业务背景**
- 高校通识课以自主学习为主，缺少“随时有人讲、随时有人答”的支持
- 泛雅 Web / 学习通移动端需要可嵌入的 AI 能力，而非独立孤岛系统

**项目定位**
- 命题企业：超星集团
- 赛题方向：智能计算 · 应用类
- 核心目标：轻量化集成泛雅，打通智课生成 + 实时问答 + 进度续接

### 讲解词

> 泛雅平台已有大量优质课件，但多数仍是静态资源。学生自学时遇到理解断点，教师又难以及时感知。AI 技术成熟后，我们有机会把“课件资源”升级为“可交互智课资源”，这正是 A12 赛题的核心方向。

## 模块 3：痛点

**本页目的：** 分角色说清楚“卡在哪里”。

### 建议标题

**三类角色的核心痛点**

### 页面内容（三列）

| 教师 | 学生 | 平台 |
|------|------|------|
| 上传课件后还要录讲解视频 | 自学遇疑无法即时获得针对性解答 | 静态资源多，智能化能力弱 |
| 讲稿制作重复、耗时长 | 提问后学习进度容易中断 | 缺少标准化 AI 能力接入方式 |
| 难以及时掌握学生困惑点 | 缺少“像老师一样讲”的结构化体验 | Web/移动端需轻量嵌入 |

### 赛题五环节缺口（可放底部小字）

```text
课件解析 → 内容重构 → 智能讲授 → 实时问答 → 进度续接
         ↑ 任一环节缺失，体验都会断裂
```

### 讲解词

> 痛点不是“没有 AI”，而是 AI 没有嵌入完整教学链路。教师端卡在内容生产，学生端卡在学习断点，平台端卡在集成与扩展。我们的方案正是针对这三类痛点分别设计。

## 模块 4：方案总览

**本页目的：** 给出全局地图——“一套底座，两端分工”。

### 建议标题

**一套 AI 智课底座，教师端与学生端分工协同**

### 页面内容

              │                                 │

> 整体采用一套底座、两端分工：教师端完成课件上传、讲稿编辑和学情查看；学生端完成播放、问答和断点续学；底层由 Go 后端和 Dify AI 中台统一支撑，对外以轻量 API 对接泛雅平台。

## 模块 5：教师端

**本页目的：** 教师端解决什么问题、带来什么效果。

### 建议标题

**教师端：从“上传课件”到“发布 AI 智课”**

### 解决的问题

| 痛点 | 我们的做法 |
|------|------------|
| 备课耗时长 | 自动解析 PPT/PDF，生成教学节点 |
| 讲稿需手写/录制 | AI 生成结构化讲稿，支持编辑 |
| 不知学生卡在哪 | 学情看板：提问、薄弱点、节点洞察 |

### 核心功能（4 点即可）

1. **课件上传**：支持 PPT/PDF
2. **智课生成**：解析 → 重构节点 → 生成讲稿/音频
3. **脚本编辑**：教师可修改 AI 生成内容后发布
4. **学情反馈**：查看提问记录、卡点、薄弱知识点

### 效果一句话

> 教师从“内容制作者”变为“内容审核者与教学优化者”，备课效率显著提升。

### 讲解词

> 教师上传课件后，系统自动完成解析和讲稿生成。教师可以在发布前编辑脚本，保证 AI 输出可控。课程发布后，还能通过学情数据看到学生在哪些节点提问最多，从而反向优化教学。

## 模块 6：学生端

**本页目的：** 学生端解决什么问题、带来什么效果。

### 建议标题

**学生端：边学边问，问完还能接着学**

### 解决的问题

| 痛点 | 我们的做法 |
|------|------------|
| 自学无人答疑 | 文字/语音提问 + 课件上下文问答 |
| 问答与学习脱节 | 返回续接页码与节点 ID |
| 理解不足无补充 | 触发重讲脚本或薄弱点讲解 |

### 核心功能（4 点即可）

1. **节点化学习**：按教学节点播放讲稿与音频
2. **实时问答**：SSE 流式回答，带当前页上下文
3. **进度续接**：问答后回到原节点继续学习
4. **学习工具**：断点、笔记、薄弱点、练习

### 效果一句话

> 学生获得“像有 AI 学伴陪读”的体验，学习不再因疑问而中断。

### 讲解词

> 学生端不是简单看 PPT，而是按节点听讲解。遇到不懂的地方可以随时提问，系统结合当前页和当前节点回答，并在回答后提示从哪个节点继续学，必要时补充重讲内容。

## 模块 8：系统架构说明

**本页目的：** 说明核心业务实体如何组织（不必展开代码）。

### 建议标题

**分层架构：交互层 · 业务层 · AI 中台 · 数据层**

### 四层架构

| 层级 | 职责 | 主要组成 |
|------|------|----------|
| 交互层 | 教师/学生操作 | Vue 教师端、Vue 学生端 |
| 业务层 | 课程、节点、进度、问答 | Go 后端（Gin） |
| AI 中台 | 解析、生成、问答、TTS | Dify（1 Chat + 1 Workflow） |
| 数据层 | 持久化与文件 | PostgreSQL、Redis、MinIO |

### 核心业务实体关系（简化）

```text
Course（课件）
  ├── CoursePage（页）
  ├── TeachingNode（教学节点）
  │     ├── 讲稿 / 音频 / 互动问题
  └── 学生 Session / 进度 / 问答记录
```

### 泛雅集成方式

- 前端：Web 页面嵌入泛雅 / 学习通 WebView
- 接口：内部 API + OpenAPI 适配层（签名、异步任务）

### 讲解词

> 架构上采用前后端分离：前端负责交互，Go 后端负责业务编排与数据管理，Dify 负责 AI 能力统一调度。这样业务迭代与 AI 能力迭代可以相对独立，也便于对接泛雅开放接口。

## 模块 9：算法细节

**本页目的：** 说明三大核心能力“怎么实现”（控制篇幅，不堆代码）。

### 建议标题

**三大核心能力：解析 · 问答 · 续接**

### 9.1 课件解析与智课生成

```text
PPT/PDF → 页级文本提取 → 章节/节点重构 → 结构化讲稿 + TTS 音频
```

- **输入**：课件文件
- **输出**：`parsed_pages` → `teaching_nodes` → 讲稿 JSON + 音频 URL
- **要点**：不是只提取文字，而是重构为可讲授的教学节点

### 9.2 上下文问答

```text
学生问题 + 当前页 + 当前节点 + 讲稿摘要 → RAG/上下文注入 → 流式回答
```

- **输入**：question、current_page、context
- **输出**：answer、source_page、need_reteach
- **要点**：答案绑定课件上下文，降低“泛泛而谈”

### 9.3 进度续接

```text
问答结束 → 理解度判断 → resume_page + resume_node_id → 继续播放或重讲
```

- **输入**：问答结果、当前进度
- **输出**：续接位置、是否补充讲解
- **要点**：问答不打断学习主线

### Dify 8 项能力（可选小表，体现中台化）

| 能力 | 作用 |
|------|------|
| parse_document | 文档解析 |
| reconstruct_document | 节点重构 |
| generate_node_script | 节点讲稿 |
| generate_audio | 语音合成 |
| ask_with_context | 上下文问答 |
| … | 其余见交接文档 |

### 讲解词

> 算法层面我们聚焦三条链：解析链把静态文件变成结构化节点；问答链把当前学习上下文注入大模型；续接链在问答后恢复学习进度。三条链通过统一 AI 中台编排，保证可维护、可扩展。

## 模块 11：创新点、设计取舍、边界

**本页目的：** 体现思考深度，避免被问“和通用 ChatGPT 有何不同”。

### 建议标题

**创新点与设计取舍**

### 创新点（建议不超过 3 个，赛题要求）

| # | 创新点 | 说明 |
|---|--------|------|
| 1 | **节点化智课结构** | 从“页”升级到“教学节点”，支撑讲授、问答、续接同一套语义 |
| 2 | **统一 Workflow 多场景编排** | 1 个 Dify Workflow + IF/ELSE 路由 7 类 scene，降低运维与对接成本 |
| 3 | **问答—续接一体化** | 问答结果直接输出 resume_page / resume_node_id，而非孤立聊天 |

### 设计取舍

| 取舍 | 选择 | 原因 |
|------|------|------|
| 大模型部署 | 云端 API（通义） | 符合 8C16G 服务器约束，不本地跑大模型 |
| AI 编排 | Dify 中台 | 能力可配置、可演示、便于赛题展示 |
| 泛雅集成 | API + Web 嵌入 | 轻量，不改造泛雅核心 |
| 降级 | Python 引擎备用 | Dify 异常时可 fallback |

### 边界说明（主动说明，显得诚实）

- 当前以 **PPT/PDF 文本解析** 为主，公式/图表深度识别为增强方向
- **语音提问** 已有接口与播报，全链路语音问答可继续完善
- **100 份样本准确率报告** 为答辩前补充项
- **学习通 WebView** 已做响应式适配，正式实测截图待补充

### 讲解词

> 我们的创新不在“又一个聊天机器人”，而在节点化智课结构与问答续接一体化。设计上优先保证赛题闭环可演示和泛雅轻量集成，部分指标与深度能力将在后续版本继续完善。
