# 启智云双端解决方案 PPT 大纲

> 适用位置：背景 / 痛点之后，架构之前的“解决方案”部分
>
> 这部分的讲述原则：先从题目需求和内容梳理出发，再给出双端解决方案总览，随后展开教师端、学生端和双端联动的功能效果，最后把算法映射收束成一张统一图。

---

## 一、先从内容梳理开始

这部分真正的起点，不是某一个技术点，而是题目要求和用户需求本身。

建议按下面顺序梳理：

1. 先看题目要求里到底要解决什么。
2. 再把这些要求翻译成教师端和学生端各自的真实需求。
3. 最后再把需求落到算法链路和页面结构上。

换句话说，这一段 PPT 的逻辑不是“先证明课件解析”，而是“先说明为什么要做这条链路，再说明课件解析怎样成为这条链路里的实现起点”。

所以更准确的表达应该是：

> 先从用户需求和教学问题出发，再说明为了满足这些需求，需要把 PPT / PDF 解析成节点化内容，进而支持讲授、问答和续接。

这样写的好处是，逻辑起点会更自然，也更容易说服评委。

---

## 二、这段内容的正确顺承关系

这里建议把顺序明确成四层：

1. **需求层**：题目要求什么，教师和学生分别需要什么。
2. **内容层**：为什么静态课件不能直接满足这些需求。
3. **方案层**：为什么必须先做内容梳理，再做课件结构化、讲授、问答和续接。
4. **实现层**：教师端、学生端、算法处理方式分别怎么对应。

所以，“课件解析是前提”这句话不要说成绝对判断，更适合说成：

> 在解决方案里，内容梳理决定方向，课件解析是最先进入实现的入口，因为它把静态文件变成了后续所有双端能力可以共同消费的学习结构。

这样表达会更稳，也更符合你刚才说的“前后顺承”逻辑。

---

## 三、建议的页面结构

如果这一段做成图 PPT，建议做 6 页左右：

1. 题目需求和内容梳理：把问题边界说清楚。
2. 双端解决方案总览：一套底座，两端分工。
3. 教师端：智课生成与讲授组织。
4. 学生端：实时问答与断点续接。
5. 双端联动故事链：教师生成到学生续学的一条完整链路。
6. 需求到算法的对应表：用户需求怎么被算法处理。

如果页数要压缩，至少保留第 1、2、3、4、5 页。

---

## 四、第 1 页：先统一前提

### 页面标题
从题目需求到节点化学习结构

### 这一页的核心句

- 题目要求先决定内容方向，内容梳理负责把方向整理清楚。
- 课件解析只是为了把方向落成可执行结构。
- 只有先把 PPT / PDF 变成可定位的知识节点，后面的讲授、问答和续接才有落点。

### 可以直接写进 PPT 的关键词句

- 静态课件 → 节点化内容
- 页级结构 → 知识点结构
- 文本提取 → 多模态理解
- 结构化脚本 → 可讲授内容
- 节点化学习底座

### 核心流程逻辑，方便绘图

原始课件（PPT / PDF）
→ 文本提取 + 图片 / 图表理解
→ 跨页语义聚合
→ 知识节点 / 讲授节点
→ 教师端和学生端共享同一套底座

### 这一页的作用

这一页不是讲技术细节，而是先建立“为什么需要这条链路”的内容关系。

---

## 五、第 2 页：双端解决方案总览

### 页面标题
双端协同：一套底座，两端分工

### 这一页的核心句

- 前面已经把需求和痛点梳理清楚了，这一页开始回答“我们怎么把它落到方案上”。
- 启智云不是两个孤立功能，而是同一套课件节点底座上的双端协作。

### 可以直接写进 PPT 的关键词句

- 一套底座
- 两端分工
- 共同节点语言
- 教师侧生成与管理
- 学生侧问答与续接
- 统一学习闭环

### 核心流程逻辑，方便绘图

题目需求
→ 内容梳理
→ 课件结构化底座
→ 教师端生成 / 编辑 / 发布
→ 学生端提问 / 理解 / 续接
→ 形成学习闭环

### 这一页要强调的点

- 这不是先讲技术，而是先给评委一张“系统怎么分工”的总图。
- 后面的教师端和学生端不是并列凑页数，而是从这张总图里拆出来的两个分支。

---

## 六、第 3 页：教师端解决什么

### 页面标题
教师端：把课件变成可讲、可改、可发布的讲授内容

### 这一页的核心句

- 教师端解决的不是“有没有课件”，而是“能不能快速形成可讲授内容”。
- AI 负责生成，教师负责把控节奏和最终呈现。

### 可以直接写进 PPT 的关键词句

- 知识点识别
- 开场白 / 讲解 / 过渡语
- 结构化脚本
- 教师可编辑
- 语音 / 数字人讲授
- 讲授节奏可控

### 核心流程逻辑，方便绘图

PPT / PDF
→ 页级摘要
→ 节点聚合
→ 脚本生成
→ 教师编辑
→ 语音合成 / 数字人播讲
→ 发布到课程

### 这一页要强调的点

- 教师端不是替代教师，而是降低讲授内容组织成本。
- 重点不是“自动生成一大段文本”，而是“生成可编辑、可复用、可播放的讲授脚本”。

### 对应题目里的用户需求

- 课件智能解析与智课生成
- 支持语音或数字人讲授
- 提供教师脚本编辑功能

---

## 七、第 4 页：学生端解决什么

### 页面标题
学生端：让提问、理解和续接连成一个学习闭环

### 这一页的核心句

- 学生端解决的不是“只给答案”，而是“在当前页、当前节点上继续学”。
- 问答不是终点，续接才是教学闭环的关键。

### 可以直接写进 PPT 的关键词句

- 当前页优先
- 当前节点优先
- 上下文问答
- 多轮交互
- 理解程度判断
- 断点续接
- 节奏调整

### 核心流程逻辑，方便绘图

当前页 / 当前节点 / 历史上下文
→ 本页优先召回
→ 上下文问答
→ 理解程度分析（none / partial / full）
→ 续接策略选择
→ 补讲 / 重讲 / 继续推进

### 续接策略可以这样画

- full：直接续讲下一节点。
- partial：先补充例子或重述，再续讲。
- none：回退到关键节点重新讲解。

### 这一页要特别说明的关系

这里的“错题复盘”不是起点，而是学生围绕课件节点学习之后暴露出来的一种结果场景。

更准确的表达方式是：

> 学生先围绕节点化课件学习，随后在提问、练习或作业中暴露出理解偏差，再由系统把问题回链到对应节点和讲授位置。

### 对应题目里的用户需求

- 多模态实时问答
- 文字 / 语音打断提问
- AI 结合上下文精准解答
- 进度智能续接

---

## 八、第 5 页：需求到算法的对应表

### 页面标题
用户需求如何被算法逐层处理

### 这一页的核心句

- 不是先有一个算法，再去找场景。
- 而是先有题目里的用户需求，再拆成对应的算法处理链路。

### 建议做成一个三列表

| 用户需求 | 算法处理方式 | 页面输出 |
| --- | --- | --- |
| 课件讲解 | 课件解析 + 跨页语义聚合 + 结构化脚本生成 | 开场白、讲解、过渡语、可编辑讲稿 |
| 实时问答 | 当前页优先召回 + 上下文关联 + 溯源生成 | 答案、sourcePage / sourceSection |
| 断点续接 | 理解程度分析 + 节奏策略 + 节点回跳 | resumePage / resumeNodeId / resumeSec |

### 如果想画成流程图，可以画成三段

1. 课件解析段：从文件到知识节点。
2. 问答生成段：从节点到带溯源的答案。
3. 续接策略段：从答案到继续讲解的位置。

### 这一页的作用

这一页是“看起来最像算法”的一页，适合把评委的注意力从场景拉回到算法处理方式上。

---

## 九、第 6 页：设计经验与取舍

### 页面标题
来自项目经验的三个设计原则

### 这一页的核心句

- 节点是全系统统一语言。
- AI 作为适配层，而不是架构中心。
- 问答必须支持续接，教学过程不能断。

### 可以直接写进 PPT 的关键词句

- 节点化统一语言
- 本页优先
- 续接优先
- 教师主导，AI 辅助
- SSE 流式交互
- 失败降级 / fallback

### 核心流程逻辑，方便绘图

核心业务目标
→ 节点化内容模型
→ AI 能力适配层
→ 外部模型调用
→ 教师端 / 学生端稳定消费

### 这一页要说清楚的经验

- 我们不是做一个孤立的 AI 功能，而是在做一个教学系统。
- 真正稳定的是“节点语言 + 业务编排”，模型只是能力提供者。
- 因为有项目实现经验，所以我们更清楚哪些环节必须拆开，哪些环节必须共用。

---

## 十、这一段最适合答辩时怎么讲

可以按下面这个顺序口述：

1. 先讲课件解析是前提，静态课件必须先变成节点化内容。
2. 再讲教师端，解决的是“怎么讲、怎么改、怎么发布”。
3. 再讲学生端，解决的是“怎么问、怎么接、怎么继续学”。
4. 然后用一张表把用户需求和算法处理方式对起来。
5. 最后收束到设计经验：节点是统一语言，AI 是适配层，续接是教学闭环的核心。

---

## 十、最适合放在这一段开头的一句话

> 我们不是先从某个使用场景切入，而是先根据题目要求梳理教师和学生的真实需求，再把这些需求落实到课件解析、节点化内容和双端算法上。
（背景-痛点:）-（问题的解决方案即思路（功能）设计: [系统的双端分别解决了什么问题+实现了什么样的功能/效果]、场景体验）- 系统的架构说明:[业务主体是如何组织起来的] - 算法细节设计: [核心算法链路是怎样的，为什么要这样设计] - 核心优势、创新点: [为什么评委会觉得这个方案好，和其他方案比有什么优势]
